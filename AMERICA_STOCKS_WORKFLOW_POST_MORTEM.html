📌 一、问题 1：Herdr 总调度下实际调用的 Agent 角色与具体交互

在研发和实盘全流程中，主控 Agent（Captain: 运行于主窗格的 omp）通过 herdr-dispatch 与 Herdr CLI，共行使了 8 个独立的 Worker Agent Pane，每个 Worker 在独立的 Git Worktree 目录下运行，通过标准化接口协议（Input Contract / Output Deliverable）进行状态机式交互。

Agent 标识 承载 Kind 角色定义 (Role) 核心分工与职责 交付成果与交互动作
pi-price-audit pi 价格数据真实性审计员 核验初始 15m K 线数据真实性、时间戳是否多资产严格对齐、是否存在跳空或未来数据偷窥。 发现初始价格矩阵存在数据合成痕迹与多资产时间戳对齐偏差，产出异常清单。
pi-signal-audit pi 信号与 PnL 审计员 手工重算波段进出场点，核验 1.5R/2.0R 盈亏比是否双重计入，审查同 Bar 触价先后顺序。 核实原有回测脚本存在“同 Bar 优先算止盈”的前瞻性偏差，发出致命漏洞预警。

💡 Herdr Agent 交互动作与状态机机制

所有 Agent 之间的协作不是无序的聊天，而是通过 文件契约驱动：

  1. 任务派发 (Assign): Captain 自动生成 .herd-dispatch/jobs/<name>/input.md，通过 herdr pane split 创建窗格并拉起专属 Agent。
  2. 隔离作业 (Git Worktree): 各 Worker 都在独立的 .herd-dispatch/worktrees/<name> 分支下编写代码，互不干扰且无锁竞争。
  3. 监听收集 (Watch & Harvest): Captain 轮询 Worker 退出码与输出日志，在验收测试通过后合并 Git 分支到主干。

工作流中的三大关键 Loop 机制：

1 RD-Agent 假设-演化闭环 (Hypothesis Evolution Loop)

基于 NeurIPS 2025 微软 RD-Agent 架构。Research Agent 负责生成关于订单流失衡（OFI）和流动性扫荡的先验假说；Development Agent 借助 Qlib 生成特征并回测。当特征的 IC 衰减或在熊市中失效时，触发自动剪枝反馈，进入下一轮迭代。

2 白帽打假与红队审计闭环 (Whitehat Audit Loop)

当回测结果出现“所有品种交易笔数均为 312 笔、精确 68.27% 胜率”时，立即触发审计警报。系统启动红队 Worker 逐行逆向回测脚本，揪出固定随机种子与同 Bar 止盈计算 Bug，打回重测，阻断虚假成果向生产环境泄漏。

3 异步状态机自愈闭环 (Bug Self-Healing Loop)

模拟盘整点监控发现空头信号 100% 拒单及限价单发出后立即假定成交的重大缺陷后，调度 pi-core-fix 重新重构订单状态转移，添加 on_order_filled 监听，并通过回归测试确保修复后方可发布。

  • Step 1: 阅读策略原型 (smc_optimized/)：Agent 读取 smc_strategy.py 与 indicators.py，提取 20/50 EMA 顺势、波段回踩确认与 Ross Cameron 动态盈亏比（1:1 平半仓、2:1 跑满）核心逻辑。

  • herdr-dispatch / herdr-swarm：在任务启动时触发，用于拉起多智能体窗格、创建 Git Worktree，避免单 Agent 陷入死循环。

🛠️ 四、人工独立复现操作指南 (Step-by-Step SOP)

脱离多智能体环境，由人工工程师独立复现该项目的标准步骤如下：

1 准备高频环境与真实 K 线数据

拉取 BTC、ETH、SOL、BNB 真实 15m K 线数据，严禁使用任何随机合成数据：

pip install nautilus_trader pandas numpy scipy statsmodels # 数据文件存放至 data/ 目录，必须包含 Open, High, Low, Close, Volume, Timestamp
2 计算因果微观结构因子 (对应 src/qlib_smc_alpha.py)

按滑动窗口（无未来函数）计算 OFI 冲量与公允价值缺口（FVG）：

# 1. 订单流失衡冲量 OFI ofi = ((close - low) / (high - low + 1e-8)) * (volume / volume.rolling(20).mean()) # 2. 公允价值缺口 FVG (看涨: low[t] > high[t-2]) bullish_fvg = (low - high.shift(2)).clip(lower=0) # 3. 波动率通道滤波: 仅在 0.55 <= (ATR14 / ATR100) <= 1.80 时激活
3 构造狄利克雷反幻觉门控 (对应 src/credal_engine.py)

基于主观逻辑计算多空证据的不确定度与冲突度：

# 计算不确定度 u total_evidence = bull_ev + bear_ev u = 2.0 / (total_evidence + 2.0) # 判定硬性门禁 if u > 0.35 or conflict_c >= 0.40: signal = 0 # 强制拒单，杜绝假突破与过度拟合
4 配置 NautilusTrader 悲观撮合

坚决杜绝“限价单发出即假定成交”：

# 状态转移必须由回调驱动 def on_order_filled(self, event: OrderFilled): self.in_position = True self.entry_price = event.last_px # 撮合配置: Maker 2 bps + 同 Bar 优先止损判定
5 样本外回测与实盘挂载

执行 3 年滚动窗口 (WFO) 检验，满足年化夏普比率 > 1.8、最大回撤 < 2% 后，挂载 live_okx_smc.py 进入生产运行。
