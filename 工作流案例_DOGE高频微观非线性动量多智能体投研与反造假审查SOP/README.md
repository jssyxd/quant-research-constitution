# DOGE 高频微观非线性动量多智能体量化投研与反造假审查标准工作流 (Standard Workflow SOP)

> **版本号**: v1.0.0 (生产与审查级标准化流程)  
> **适用范围**: 高频微观结构 (Microstructure)、Meme 资产动量、订单簿排队与流动性冲击、深度时序模型（CNN/LSTM/Attention）以及需要严格防止 AI 未来函数泄露/数据伪造的量化投研项目  
> **底层调度基建**: `Herdr Dispatch` 多智能体协同总线 + `Laya-Reasoning` 认知加速 + `Binance/OKX` 官方真实公共归档 + `Anti-P-Hacking CI` 自动化审计看门狗  
> **核心宪法原则**: **【物理数据溯源、三权分立制衡、彻底剔除未来函数、严格双重会计簿记、零容忍迎合伪造】**

## 二、智能体角色分配与权责矩阵 (Agent Role Matrix)

在多 Agent 协同体系中，必须建立**“研发、执行、审计三权分立”**机制，杜绝“既当运动员又当裁判员”导致的欺骗、指标自选美化与跨项目记忆污染。

| 智能体角色 (Agent Role) | 建议 CLI / 运行环境 | 职能定义与边界 (Mandate) | 准用工具集 (Allowed Tools) | 严禁行为 (Forbidden Actions) |
| :--- | :--- | :--- | :--- | :--- |
| **总指挥架构师 (Captain Orchestrator)** | `omp` / `claude-opus` 或 `gemini-3.8-flash-high` | 拆解工作分解结构 (WBS)、分派任务至 Herdr 子窗格、状态推进、协调冲突、最终合并交付。 | `herdr-dispatch`, `read`, `todo`, `write` | **严禁亲自编写回测撮合计算逻辑**；严禁擅自修改审计结论；严禁在未获审计通过前提前发布正式策略。 |
| **认知加速过滤器 (Laya Reflex Hook)** | `Laya MCP` (`laya_predict` / `laya_decide`) | 提供亚秒级非自回归校准反射：任务类型分流 (`problem_type`)、方案路线优选、破坏性 API 变更拦截。 | `laya_predict`, `laya_decide` | 严禁超时重试阻塞系统；严禁传入未经英文规范化的生文本以防延迟加载。 |
| **文献与基准探索员 (tv-web Researcher)** | `pi` / `agent-reach` | 广泛检索学术文献（arXiv/SSRN）、TradingView 优秀开源指标、衍生品高频研报，提取数学原理。 | `agent-reach`, `web_search`, `read` | 严禁凭空发明未经验证的数学假说；严禁篡改原作者的基准定义；必须附带论文完整编号与公式来源。 |

| **执行与风控专家 (Execution Specialist)** | `omp` / `python3` | 建立 Almgren-Chriss 平方根冲击滑点模型，设计现货/永续双通道路由，建立严格双重簿记与 MMR 强平线。 | `python3`, `math` | **严禁现货零本金免息借贷记账漏洞**；严禁省去杠杆维持保证金强平线；严禁省略交易手续费。 |

## 四、各阶段交付标准与下游流转卡点 (Milestone Quality Gates)

```
[Phase 0 立项] ──(Gate 0)──> [Phase 1 数据] ──(Gate 1)──> [Phase 2 因子/模型] ──(Gate 2)──> [Phase 3 执行] ──(Gate 3)──> [Phase 4 回测] ──(Gate 4)──> [Phase 5 审计]
```

### 1. Gate 0: 课题立项审查卡点
- **准入标准**：
  1. 用户目标指标（CAGR、Sharpe、MaxDD、容量）已固化写入 `README.md` 第一节，声明为最终验收约束；
  2. 检索并收录至少 1 篇顶级量化理论论文（arXiv/SSRN）作为数学支撑，写入 `THEORY_PAPERS.md`；
  3. Laya 路由判定完毕，建立独立的研发目录，严禁与存量项目共享会话记忆。

### 2. Gate 1: 数据真实性与因果完整性卡点
- **准入标准**：
  1. 数据文件必须来源于真实交易所归档（必须附带自动下载与对齐脚本，如 `download_real_binance_doge.py`）；
  2. 执行因果静态检查：`grep -rn "np.roll.*-"` 与 `grep -rn "shift(-"` 结果必须为 0；
  3. 数据时间跨度必须满足统计样本量要求（高频 5m 至少 8,000 根以上，日线至少 1,500 交易日以上）。

### 3. Gate 2: 因子与模型纯正性卡点
- **准入标准**：
  1. 9 大微观特征输入必须完全基于过去历史（$t \le \text{current}$）；
  2. 特征字典输出严禁附带 `fwd_ret`、`future_profit` 等前瞻标签；
  3. 模型具备超低延迟推理能力（NumPy 矢量化或高效 ONNX/PyTorch），且具备波动率爆发门控机制。

### 4. Gate 3: 真实物理摩擦与严格记账卡点
- **准入标准**：
  1. 必须根据策略管理容量（如 1500 万 CNY）配置 Almgren-Chriss 平方根冲击滑点模型，严禁零滑点；
  2. **现货通道严格扣款**：买入现货必须执行 `cash -= (order_usd + trade_fee)`，严禁零本金借贷；
  3. **合约通道强平保护**：必须实时核算维持保证金率，当 $\text{Equity} < \text{MMR} \times \text{PositionValue}$ 时强制市价清算出场。

### 5. Gate 4: 盲测与反过拟合检验卡点
- **准入标准**：
  1. **Walk-Forward 效率**：严格切分 60% 样本内 (IS) 与 40% 样本外 (OOS)，必须满足：
     $$\text{WFE} = \frac{\text{Sharpe}_{OOS}}{\text{Sharpe}_{IS}} \ge \mathbf{60.0\%}$$
  2. **1,000 次蒙特卡洛置换**：95% 置信度最大回撤必须位于风险限额之内，破产概率严格为 $0.00\%$；
  3. **破坏性扰动压测**：在 $\pm 10\%$ 盘口深度噪声 + 强制 1 根 Bar 网络延迟 + 30% 手续费惩罚下，策略不得发生崩塌性巨亏。

### 6. Gate 5: 独立红队法医审计与双向收敛决议 (Final Verdict)
- **终审裁决流转**：
  - **路径 A【正式毕业】**：完全满足真实数据、无未来函数、完全对账、WFE $\ge 60\%$、且具有真实正向 EV，由审计员签发合格证书，晋升正式策略库（如 `001`～`009`）；
  - **路径 B【待研池封锁】**：逻辑自洽，但现有公开样本不足或缺乏深度订单簿排队支持，在 `to-research/README.md` 明确标注 **【需要补充 XX 数据继续研究】**，保持封锁；
  - **路径 C【建议放弃投入】**：在真实市场数据和反过拟合检验下，因物理摩擦（如做市价差低于手续费）或假突破频发，实测证实为负期望 EV（如白银 SMR 实亏 -88%，FVG 15m 费率占 418%），在 `to-research/README.md` 明确标注 **【因为 XX 验证无论如何都无法在反过拟合情况下真实出现正向 EV，建议放弃投入】**，停止资源浪费。

## 五、实盘生产避坑规范清单 (Production Incident Protocols)

所有策略在进入实盘或模拟盘部署前，必须逐项核对并实装以下五大工程级防护规范：

1. **客户端订单 ID 格式与全生命周期追踪**：
   - 订单 ID 必须采用 `O{时间戳}{计数器}` 格式（如 `O202610160945001001`），严禁使用自增简单纯数字；
   - 必须实现 `on_order_denied` 与 `on_order_canceled` 回调，任何未成交订单必须有看门狗追踪。
2. **冷启动历史 K 线 REST 预热防瞬态冲击**：
   - 策略启动时必须通过 REST API 回填至少 200 根历史 K 线预热指标，严禁在指标半成品状态下发出交易指令。
3. **平仓单强制 `reduce_only` 约束**：
   - 所有止损与止盈委托必须强制打上 `reduce_only=True` 标签，杜绝因网络延迟导致的平仓单意外变成反向开仓。
4. **限价单生命周期 TTL 撤单防逆向选择**：
   - 挂单必须设置生存时间（TTL），超过 3 根 K 线未成交判定为行情漂移失效，必须主动撤单重算。
5. **连续亏损自动熔断与冷静期机制**：
   - 连续发生 3 笔止损，系统强制进入 **30 分钟冷静期 (Cool-down Period)**，完全暂停开仓，防止震荡行情来回磨损。
